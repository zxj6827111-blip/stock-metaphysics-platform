# 方法论与研究纪律 · Phase 1

> 这份文档回答一个问题：**凭什么相信（或不相信）系统给出的结论？**

---

## 1. 核心立场

本项目**不做**以下假设：

> ✗ 「传统术数一定能预测股票」
> ✗ 「财星出现 = 股价上涨」
> ✗ 「三合局形成 = 利好」

本项目**做**以下假设：

> ✓ 传统术数是**确定性可计算**的符号系统
> ✓ 它可以被拆解为**结构化、可复现的因子**
> ✓ 这些因子与真实历史行情的关系**可以用统计方法检验**
> ✓ 检验结果**可能是"没有关系"** —— 而这同样是有价值的结论

因此系统的输出形态是：

```
股票代码
  → 确定性排盘（可审计）
  → 结构化因子（可追溯）
  → 历史数据对齐（as_of 严格隔离）
  → 统计检验 + 负对照（可复现）
  → 如实结论（包含"无效"）
```

## 2. 确定性计算原则

### 2.1 为什么禁止 LLM 算盘

| 问题 | 后果 |
|---|---|
| LLM 是概率模型，同样的输入可能给出不同干支 | 结果不可复现，"为什么上次算 83 分这次 76 分"无法回答 |
| LLM 会幻觉出不存在的节气/神煞 | 数据错误无法被发现 |
| LLM 无法被单元测试覆盖 | 无法回归 |
| LLM 无法追溯"这个地支是从哪来的" | 破坏证据链 |

**结论**：所有排盘、节气、十神、藏干、纳音必须由代码产生。
LLM（Phase 2）只能解释已经算好的结构化结果。

### 2.2 第三方库的定位

| 层 | 谁负责 | 能否替换 |
|---|---|---|
| 历法换算（公历↔农历↔干支↔节气） | lunar-python | ✅ 可替换（只要通过 Golden Case） |
| 命理关系（十神、藏干、刑冲合害、旺衰、格局） | **本项目 `src/core/constants.py` + `src/engines/bazi/rules.py`** | ❌ 本项目自持，保证一致性 |
| 因子化 | 本项目 | ❌ 核心资产 |
| 统计验证 | 本项目 | ❌ 核心资产 |

**为什么命理关系要自持**：不同库对十神、藏干权重、旺衰算法的实现差异很大，
如果直接用库的输出，未来换库会导致所有因子口径变化。把"关系运算"握在自己手里，
换库时只需要验证历法部分。

## 3. StockBirthProfile：把假设变成可检验的对象

股票没有出生时间。"上市首日开盘"只是一个**工程选择**，不是事实。

因此系统：

1. **版本化**：`birth_profile_version = v1`，切换基准生成新记录而非覆盖；
2. **记录证据链**：`evidence.derivation` 写清"哪天、哪个 session、几点、什么时区"；
3. **记录假设**：`assumptions` 明确说明"这是研究假设，不是定论"；
4. **预留候选**：`ipo_date` / `company_foundation` / `first_trade` / `custom`；
5. **不硬编码**：开盘时刻来自 `exchange_session_calendar` 配置，
   由 AST 测试强制检查业务代码中不得出现 `09:30` 字面量。

**Phase 2 应该做的事**：用同一套因子体系，分别用不同出生基准回测，
看哪一种在历史数据上更稳定。**在此之前不预设哪一种正确。**

## 4. 股票无性别：一个必须显式处理的建模问题

传统大运顺逆依赖「性别 + 年干阴阳」：

```
阳年男 / 阴年女 → 顺排
阴年男 / 阳年女 → 逆排
```

股票没有性别。如果系统偷偷填"男命"，会得到一个**伪精确**的结果 ——
它看起来算出来了大运，但那个大运没有任何依据。

本项目的处理：

| 措施 | 实现 |
|---|---|
| 默认不适用 | `variant_mode = not_applicable`（默认值） |
| 不输出大运 | 该模式下 `da_yun = []` |
| 不进入因子 | 大运不参与任何 Phase 1 因子（有硬断言：variant 变化时因子值必须完全不变） |
| 记录假设 | `assumptions` 中含 `bazi.variant_mode`；由首日阴阳推导时另有 `birth.variant_basis` |
| 允许研究 | 显式传 `forward` / `reverse` / `both` 才计算，且标注"基于假设规则" |
| 允许推导（2026-09-23） | `variant_basis=first_day_yinyang`：按「首日收涨→阳→男命 / 首日收跌→阴→女命」假定方向；缺首日数据不推导、不默认。口径见 [ADR-0014](ADR/ADR-0014-first-day-yinyang-variant-basis.md)，真源 `src/core/stock/variant_basis.py` |
| 机器校验 | `tests/engines/test_bazi_engine.py::TestNoGenderContract`（含 §5.4 因子不变）、`tests/test_birth_profile.py::TestFirstDayYinyangBasis`、`tests/integration/test_api_variant_basis.py` |

UI 上也如实展示：

```
运限假设：顺行（假设规则）　首日涨跌标识「阳」（首日 +3.01%）→ 男命假设 → variant_mode=forward
大运（假设规则）  起运前 2001–2007 · 乙未 2008–2017 · 甲午 2018–2027（当前）· …
注：运限推演基于假设规则，非事实（股票无真实性别），不进入任何因子。
```

## 5. as_of 单向隔离与防未来数据泄漏

### 5.1 规则

```
as_of = 2020-01-01

特征（因子）：只能读 ≤ 2020-01-01 的信息
标签（收益）：只能读 >  2020-01-01 的信息
```

### 5.2 实现

| 机制 | 位置 |
|---|---|
| 唯一裁剪入口 | `src/market/normalization/frames.py::clip_to_as_of` |
| 研究层封装 | `src/research/labels/forward_returns.py::visible_slice` |
| 结构隔离 | `src/factors/` 不得 import 标签模块（测试强制） |
| 标签可用性标记 | `LabelSet.horizon_available` |

### 5.3 验证方法：哨兵污染

`tests/test_no_future_data_access.py` 的做法：

```python
# 把 as_of 之后的行情全部替换成 999999
contaminated = series.model_copy(update={"bars": [
    b.model_copy(update={"close": 999999.0}) if b.trade_date > AS_OF else b
    for b in series.bars
]})

# 特征结果必须完全不变
assert _stats(clip_to_as_of(clean, AS_OF)) == _stats(clip_to_as_of(contaminated, AS_OF))
```

同时有一个**反向对照**：

```python
# 标签必须随未来数据变化 —— 这证明标签确实来自未来
assert l_clean.ret_20d != l_dirty.ret_20d
```

这个反向对照很重要：如果标签也不变，说明标签实现有 bug（而不是"没有泄漏"）。

## 6. 「上涨」的多重定义

牛市中所有因子都会显得"很准"。因此系统对「上涨」给出四种定义：

| 定义 | 判据 | 用途 |
|---|---|---|
| `absolute_up_20d` | `ret_20d > 0` | 最宽松，受大盘影响最大 |
| `excess_up_20d` | `ret_20d − bench_20d > 0` | 剔除大盘涨跌 |
| `strong_up_20d` | `ret_20d > 10%` | 只看显著上涨 |
| `drawdown_controlled_up_20d` | `ret_20d > 0` 且 `max_drawdown_20d > −10%` | 收益与风险兼顾 |

事件研究同时输出 `up_rate`（绝对上涨率）与 `excess_up_rate`（超额上涨率），
**不允许只报一个**。

## 7. 事件研究的方法细节

### 7.1 activation 语义（一个真实踩过的坑）

最初的实现里，"因子命中"意味着"这个因子被计算过"。
结果：真实组与对照组（随机出生日、±7 天）的**事件集合完全相同**，
因为无论出生日是哪天，65 个因子都会被算一遍。

于是负对照输出的 `control_mean_return_20d` 与 `real_mean_return_20d` **完全相等**，
所有对照都显示 "tie" —— 这不是"术数因子无效"，而是**方法本身失效**。

修复方式：引入 `activation` 参数。

| 取值 | 含义 |
|---|---|
| `any` | 只要算了该因子就算命中（仅用于随机因子对照） |
| `nonzero`（默认） | `normalized_value != 0`，即"该传统结构确实成立" |
| `positive` / `negative` | 只看正向 / 负向命中 |

**教训**：负对照的正确性依赖于"事件定义必须有区分度"。
如果真实组和对照组的事件集合一样，对照就没有任何信息。

### 7.2 指标口径不混用

`mean_excess_return` / `max_drawdown` / `mean_max_return` 只在 **20 日**持有期输出。

原因：超额收益按 20 日计算，如果在 5 日持有期那一行也填这个数，
读者会把"20 日超额"误读成"5 日超额"。其他持有期返回 `null` 并在 `note` 中说明。

### 7.3 事件与标签的对齐

`as_of` 可能落在非交易日（例如月中某天）。对齐规则：

```
因子观测 (stock_code, as_of)  →  标签 trade_date（>= as_of 的第一个交易日）
```

未匹配到标签的观测**直接剔除**，而不是补 0 或前向填充。

### 7.4 样本不足时

```
sample_count < 8   → note 中标注"低于阈值，统计结果不具参考性"
sample_count < 30  → note 中标注"样本偏少，置信区间较宽"
sample_count == 0  → 所有统计量返回 null，note 说明原因
```

**永远不用 0 填充缺失的统计量。**

## 8. 负对照：本项目可信度的核心

### 8.1 四类对照

| 类型 | 做法 | 检验什么 |
|---|---|---|
| 随机出生日期 | 在上市日 ±10 年内均匀随机取一天，**重排盘、重算因子** | 真实命盘是否优于随机命盘 |
| 出生日期 +7 天 | 平移一周（保留星期结构，破坏具体日期） | 真实出生日是否有信息量 |
| 出生日期 −7 天 | 同上，反向 | 排除单侧偏差 |
| 随机因子 | 保持命中比例，随机选择命中的（股票, 交易日） | 真实因子的**选择性**是否有信息量 |

> **关键**：前三类对照必须**真的重排盘、重算因子**，
> 不能拿真实因子去比随机标签 —— 那样检验的就不是"命盘是否有信息量"了。

### 8.2 判定标准

```
outperform   : Δmean_return(20D) > 0.2%  且  Δup_rate > 0  且  双方样本 ≥ 20
underperform : Δmean_return(20D) < −0.2% 且  Δup_rate < 0  且  双方样本 ≥ 20
tie          : 差异小于阈值
inconclusive : 任一组样本 < 20，或数据为空
```

### 8.3 输出纪律

**如果真实因子并不优于随机，系统会如实输出。**

实际运行输出示例：

```
random_birth_date → tie          | real= 0.019284  ctl= 0.019104
shift_plus_7d     → outperform   | real= 0.019284  ctl= 0.017249
shift_minus_7d    → tie          | real= 0.019284  ctl= 0.019104
random_factor     → tie          | real= 0.019284  ctl= 0.019104

结论：对照结果不一致：优于随机 1 类、无差异 3 类、弱于随机 0 类。
      结论为**不确定**，不能宣称有效性。
```

**注意 `real` 与 `ctl` 的数值确实不同** —— 这是 activation 修复后的正确表现。
修复前所有对照的 ctl 都等于 real，看起来"干净"但完全无效。

系统**不会**做这几件事：

* ✗ 只报告表现好的那一类对照
* ✗ 把 `tie` 描述成"接近有效"
* ✗ 用"样本还不够"掩盖 `underperform`
* ✗ 反复调整参数直到出现 `outperform`

## 9. 古籍知识中心的纪律

### 9.1 必须同时检索反证

`EvidenceBundle` 固定包含三个分区：

```
supporting_evidence  支持当前规则/结论
counter_evidence     与当前规则/结论相反
neutral_evidence     中性背景
```

这样做的目的是**降低"先有结论、后找古籍"的问题**。

实际效果示例：检索「财星 + 身财对比」时，系统返回：

* 支持：滴天髓「何知其人富，财气通门户」、渊海子平「财为养命之源」
* **反证**：子平真诠「财格之贵，在于身强而任财」、滴天髓「财多身弱，正谓富屋贫人」、
  渊海子平「财多身弱，反为不美」、神峰通考「财多身弱，富屋贫人」、渊海子平「比劫重重，财源难聚」

**六条反证 vs 两条支持** —— 这直接说明"财星多 = 利好"在传统命理内部也不是共识。

### 9.2 神煞类字段的低置信度处理

清代陈素庵《命理约言》明确批评神煞体系（"神煞之说，多不可信，学者当以五行生克为正"），
该条文本就收录在语料中，并作为 `H_DAY_006`（建除）、`H_DAY_007`（黄黑道）、
`H_DAY_008`（十二神）、`H_DAY_011`（星宿）的反证条目。

对应的，这些因子的 `confidence` 被刻意压到 **≤ 0.55**。

### 9.3 版权

* 只收清代及以前刊行的公版原文；
* 每条带 `license_status` / `edition` / `provenance`；
* `modern_note` 是本项目自撰，不引用未授权的现代整理本（测试强制检查常见出版社名）；
* ⚠️ **Phase 1 未逐字对照权威刊本校勘** —— 语料 `_meta` 中有明确声明，
  正式发布前必须完成校勘。

## 10. 已知局限（必须向用户说明）

### 10.1 统计层面

| 局限 | 说明 |
|---|---|
| **样本量小** | Phase 1 的研究流水线默认 10 只股票 × 每季度采样，样本常在几十到几百量级 |
| **多重检验** | 65 个因子反复检验，必然有部分"看起来有效"的属于偶然（未做 Bonferroni / FDR 校正） |
| **无样本外验证** | Phase 1 未划分 in-sample / out-of-sample；结论不可外推 |
| **无 IC / 因子相关性分析** | 尚未计算因子的信息系数与共线性 |
| **生存者偏差** | 未处理退市股票 |
| **复权方式** | 当前统一使用前复权（qfq），未对比不复权/后复权的影响 |
| **行业与市值偏差** | 未做行业中性化、市值中性化 |

### 10.2 方法层面

| 局限 | 说明 |
|---|---|
| **五行力量权重是工程近似** | 天干 1.0 / 月支 ×1.5 / 日支 ×1.2 / 藏干 0.6-0.3-0.1 是自定权重，不同流派差异很大 |
| **格局判定有流派分歧** | 采用子平通行法（月令本气/透干），盲派、新派结论可能不同；系统输出 confidence 与候选列表 |
| **用神判定带主观性** | 扶抑法为主、调候法为辅；置信度较低时会显式告警 |
| **黄历流派差异** | 宜忌、建除等字段在不同通书间存在差异，系统采用 lunar-python 内置口径 |
| **大运未纳入** | 因股票无性别，Phase 1 不输出大运、不纳入因子 |
| **交易日历不完整** | 无独立交易日历表，节假日上市的股票会被错误对齐（质量等级已降级） |

### 10.3 领域层面（最重要）

> **传统八字、紫微斗数、黄历、六爻、奇门与股票未来收益之间，
> 不存在经过现代金融科学确认的稳定因果关系。**

本系统的价值不在于"证明术数有效"，而在于**用一个可复现的框架去检验它**，
并诚实地报告结果 —— 包括"没有发现关系"。

因此平台**不提供**：自动交易、券商下单、资金账户、收益保证、投资建议。

## 11. 研究者的检查清单

在引用系统的任何统计结论之前，请确认：

- [ ] 样本数是多少？（`sample_count`）
- [ ] 是绝对上涨率还是超额上涨率？（`up_rate` vs `excess_up_rate`）
- [ ] 超额收益是哪个持有期的？（只在 20D 有效）
- [ ] 负对照跑了吗？四类结果分别是什么？（`negative_controls.results`）
- [ ] 结论是 `outperform` / `tie` / `underperform` / `inconclusive`？
- [ ] 做过样本外验证吗？（Phase 1 **没有**）
- [ ] 这是"术数共识"还是"历史统计"？（这是两个完全不同的指标）
- [ ] 数据的 `is_degraded` 是否为 `true`？（合成行情不能用于任何判断）
