## 修改与语义

1. **八字顺逆与兼容性别一致。** `smx-bazi-native` 根据原局年干阴阳和实际顺/逆变体反解“男命/女命兼容参数”。页面同时展示当前方向使用的兼容参数、对照方向的兼容参数，并明确股票不存在真实性别。没有把“顺行”固定映射为“男命”。规则修正升级到 `smx-bazi-native-1.0.2`，差异登记在 `docs/calculation-differences-phase1.md` 的 D7。
2. **日期扫描避免无效重算。** 仅复用已核验仍适用于原局关系的 `smx-bazi-native-1.0.0` 静态缓存投影，并继续校验干支和日主；其他未知旧版本仍拒绝复用。全市场百分位改为一次排序和并列平均秩，保持旧统计定义。
3. **时间窗口只在选择后计算。** 时间轴首屏只加载逐日窗口；月度在选择月视图后读取，周度在点击加载后读取。初次分析请求也在面板内去重。
4. **复用逐日结果与历法快照。** 同一进程中的时间窗口共用最多 600 条带完整股票、出生时刻、日期、采样时刻、变体和引擎/规则/配置版本键的逐日计算结果。单次批量计算中，八字和黄历共享同一批历法快照；因此重叠日期无需重新生成盘面。
5. **紫微大批量并行。** 紫微批量达到 16 条时最多使用 4 个 Node worker；较小批量维持串行。成功结果仍按输入顺序返回，错误继续携带原输入索引；同一 `buildZiweiChart` 计算函数和引擎版本不变。

### 性能复测

- 日期关系扫描真实本地全市场输入为 5,796 个标的：冷缓存 1.884 秒、5,796 条有效扫描；热缓存 0.289 秒。此前基线耗时 106.425 秒且有效扫描为 0，旧缓存校验导致大量无效重建。该对比同时包含“从无有效结果到有效结果”的修复，不应解读成完全相同工作量的纯速度倍数。
- 周度 API 使用真实本地分析记录冷缓存返回 12 周/60 个交易日用时 6.371 秒；同一请求热缓存 24 毫秒。浏览器的完整交互顺序中，逐日结果先加载后，周度请求约 5.319 秒；这次有 20 个重叠日期可复用。月度请求返回 12 行约 4.515 秒。另一次隔离 Python 直接调用逐日 API 冷请求为 4.531 秒。
- 浏览器计时受本地 Next 开发编译、页面加载和并发进程影响。首次月/周计算仍需要实际历法与紫微排盘；周视图包含 60 个每日结果，冷请求仍不是即时响应。重复请求已通过版本化进程缓存降至毫秒级。
