# W4 历史研究数据集工程验收（2026-09-28）

## 范围与状态

本工作包实现特征/未来结果分离、按 `security_id + research_date + versions` 严格一对一联结、security/year Parquet 分片、SHA-256 清单、失败/续跑账本，以及 DuckDB 查询。研究特征沿用 F4 快照和现有 calendar、Bazi、Huangli 因子计算；未来标签仅由 W3 `compute_forward_returns()` 根据未复权 raw bars 与同日复权因子计算。

**结论：W4 软件工程样本通过；完整认证历史面板未生成，研究资格仍为 NO-GO。** 这里的 `manifest.status=COMPLETE` 仅表示本次 20 行工程样本分片写完，不表示认证范围完整或可用于确认性研究。

## 实现

- `src/research/historical_dataset.py`：校验身份/日期/版本、15:00 Asia/Shanghai、标签口径、manifest 与 artifact digest；原子写入分离的 features/outcomes Parquet；以输入 digest 幂等续跑；拒绝已完成分片的输入变化；DuckDB 仅查询 manifest 登记且 SHA 匹配的配对分片。
- `scripts/build_w4_historical_dataset.py`：读取并校验 W2 文件、raw/factor manifests、content-addressed NPZ、Security/PIT 物理范围和本机出生档案；每个研究日重新核对 PIT、观察日范围与当日 raw/factor；调用 F4 和确定性因子计算；未来 bars 不传入特征函数；以 `chart_artifact` 保存 Calendar、Bazi、Huangli 原盘，并保存引用及可复核 checksum。全量 manifest/blob digest 记录在数据集/分片 provenance 中；逐日出生证据只引用最早可观测日线日期和稳定来源类型，因此只改 T+ 行情不会改 T 的因子值或 chart artifact ID。
- `tests/research/test_historical_dataset.py`：严格连接、重复/漏行/版本冲突、版本化分片、恢复、失败记录、digest 损坏检测、未来行情隔离测试。
- `.gitignore`：忽略生成目录 `data/research_datasets/`；样本 Parquet、manifest 和本机 SQLite 不入 Git。

原始盘 checksum 是对标准化 artifact writer payload 计算的 SHA-256。验收时从 SQLite 独立重建 60 个 artifact payload，60/60 与 Parquet 中的引用 checksum 一致。

## 数据资格与规模边界

样本锁定的输入：

- W2 manifest 文件 SHA-256：`e60d137e47073f1891d83544d0b382e9010be1063ca3764eee85f878e7da9d6e`。
- W2 状态仍是 `PHYSICAL_SCOPE_LIMITED`；`full_pit_universe_status=COVERAGE_INCOMPLETE`；确认性研究资格为 `NOT_GRANTED_BY_DATA_PHYSICAL_AUDIT`。
- raw overlay manifest/blob SHA-256：`461643b4411f98528045173945990bfc7f07b910ceac72a769cae424edb13243` / `9c6af84c56e1a9dd2f93a50c66fd70aa9b295335529bd7d78d80cd3dd485f27f`。
- factor manifest/blob SHA-256：`1898c27981d76429209be19e6254a2a807c2bd9909b41e0bdd8d5d7a50bf1452` / `4c7fa8110005f6c35be0434b258a39b6a51e48fb833306ee01553f5512d3f4a4`。
- reference calendar digest：`5674cd0a71371c36704a2a8ba1543875e75da7bfa327ea09398071f24bdde113`。SSE/SZSE 来源是独立 observed-index 日期；它不是官方交易所日历，尚未用停牌和 ST 状态解释所有缺口。

W2 物理范围行合计有 **16,819,837 个 raw/factor/reference-date 交集观察**，分布在 5,863 个有交集身份。这是物理候选交集，不是认证研究范围；不能据此批量生成或发布研究结论。

样本首次端到端处理约 2.7 秒，即约 7.5 行/秒。按该小样本直线外推到 16,819,837 个候选观察约需 **26 天单进程连续运行**；样本合计约 5.37 KB Parquet/行，粗略外推约 90.2 GB Parquet。每行当前保存 3 个 chart artifacts；按 60 条实测 artifact 的 JSON payload 均值约 34.5 KB 估算，约需 1.74 TB JSON payload，尚未计 SQLite 索引、事务/WAL 和运行余量。上述是早期容量估算，受单证券小样本影响，不是承诺工期或精确磁盘需求。

**停止完整面板生成的依据**：W2 没有发布完整 PIT 认证区间；5,534 条原始序列仍待物理核验，复权因子只有局部样本完成物理核验，挂牌日期和历史出生证据也未全部达到 as-of 证明要求；参考日历和缺口分类仍有限。当前工程样本并未越过这些门槛。待 W2 有可发布的逐证券可用范围、可追溯的 PIT/出生证据和资源规划后，再用相同 schema 生成指定范围，不能把本样本改标为全历史或研究就绪。

因此 W4 的本地查询/重放管道和工程样本已交付；**完整认证面板为 BLOCKED BY W2，不是 PASS，也不阻塞继续实现独立的软件包 W5–W8。**
