# UI 效果图差距分析与修正方案

日期：2026-09-20。基线 HEAD：`4d3990ebd12dda08bd0aaa08f2830aad8df9b5c8`。

## 1. 结论与证据边界

**现有 UI 已有页面和组件基础，但不满足参考图视觉还原验收。主要差距是视觉语言、首屏布局、后续页面的信息架构，以及部分数据映射缺陷；不是简单换色或字体微调可以解决。**

推荐保留 Next.js、现有组件和后端计算体系，开展“参考图布局恢复 + 真实数据展示修复 + 视觉验收补齐”。不需要重写整个系统。

本次检查：

- 实际查看 `doc/ui-reference/01–10` 全部参考图，以及仓库原有十页截图。
- 阅读 UI 规范、参考包提示词、Phase 1/2 UI 实现说明、页面和共享组件、数据映射及截图测试代码。当前工具未提供 CodeGraph，采用本地文件检索。
- 启动独立的本地前端检查服务（3100），通过 Playwright MCP 重新截图：01–03 为显式 fixture，04–10 为正常 API 模式；viewport 固定 1672×941。
- 实测 DOM 几何尺寸、CSS 变量和黄历接口响应；时间窗口等待请求完成后另存终态截图。
- 本次没有修改产品代码，没有执行完整构建、pytest 或 E2E 套件；属于 UI 专项诊断，不是生产可用性验收。
- 检查期间工作区出现其他 Phase 4 未跟踪文件，未改动这些文件。现场截图对应本次读取的工作区，不能当作整个仓库的冻结验收。

截图与对照：[`十页对照查看器`](../output/playwright/ui-audit-20260920/index.html)。截图名称带 `fixture` / `live`，避免把演示与真实 API 数据混为一谈。live 仅表示使用正常 API 路径，不等于行情已经被核验为真实。

## 2. 为什么看起来不像

### 2.1 东方视觉识别被过度简化

参考图使用金色宋体风格标题、细节丰富的太极星盘、低亮度山水背景、书籍装饰及较大图标；当前使用粗黑体标题、简单同心圆和小线性图标。底色虽接近，但品牌识别明显改变。

`TopBar.tsx` 的品牌标题为白色 sans，`PageHero` 继承 sans；`globals.css` 虽定义 `--font-serif-cn`，但没有用于这两处。不是仅仅 PingFang 与微软雅黑的字形差异。

允许做独立 SVG 山形、星盘、印章与书籍装饰；禁止整页 PNG 或带文字截图充当网页。装饰只放在头图区和边角，不影响盘面与正文可读性。

### 2.2 首屏信息密度和空间分配偏离

同尺寸观察值如下。参考值为图片人工估读，当前值为浏览器 DOM 测量，均取近似整数 CSS px。

| 页面/区块 | 参考图 | 当前 fixture | 影响 |
|---|---:|---:|---|
| 综合页模型区顶部 / 高度 | y≈244 / h≈197 | y≈270 / h≈279 | 第一排明显过高 |
| 综合页历史摘要顶部 | y≈728 | y≈1029 | 关键研究结论离开首屏 |
| 八字页盘面区顶部 / 高度 | y≈242 / h≈270 | y≈314 / h≈368 | 上下文和盘面都占用过多高度 |
| 八字页正负因素顶部 | y≈690 | y≈912 | 首屏几乎看不到因子内容 |
| 八字页古籍区顶部 | y≈859 | y≈1230 | 证据链被推到屏幕下方 |
| 首页系统状态宽度 | ≈445 | 400 | 与最近分析的比例不同 |

`StockContextBar` 的 `flex-wrap` 导致按钮另起一行；八字页又叠加导航行。综合页使用整行 grid，把时间窗口与长证据列表放在同一行，行高容易被内容撑大，下一行历史统计一起下移。

修正不能简单把所有文字缩小：当前正文和导航本来已经偏小。应改列布局、控制摘要长度、把长解释放入详情层，并保留必要的状态提示。

参考图自身的侧栏也不完全一致：01/03 约230px，02约175px，其他页介于其间。因此不能机械追求十张图每个像素都相同；需要先统一一套桌面 shell 尺寸，再逐页恢复内容区比例。

### 2.3 后续页面从研究仪表板变成了纵向表单

Phase 2 的 `ResearchPage` 只提供 shell 和 `space-y-3`；很多页面随后直接纵向排列 `Card`。复用了外壳，但没有复用或实现参考图的页面栅格。

`Card` 自身没有内容区 padding；早期页面手动加了 `p-3.5`，后续多个页面直接把内容放入 Card，所以出现贴边文本、不一致内边距、默认输入框与过亮边框。

## 4. 已确认的实现缺陷

### P0：黄历字段映射错误

- API `GET /api/v1/analysis/AN-20260920065505-600519-c8f8e5/huangli` 本次返回 200。
- 响应 `huangli` 包含 `generated_at / engine_version / primary / days`；`primary` 有日期、农历、干支、节气、冲煞、宜忌等完整字段。
- 页面 `apps/web/app/stock/[code]/huangli/page.tsx:57` 从 `h.day`、`h.today` 取值，没有读取 `h.primary`。
- 后端 `_raw_payload` 在 `src/engines/huangli/huangli_engine.py:123` 明确写入 `primary`。

修正前端类型和字段映射，继续核对每个展示字段名称；用真实响应形状做回归，不能把当前错误归因于后端没有数据，也不需要改 v1 API。

### P0：正常模式与 fixture 未完全隔离

- `app/page.tsx:173` 无条件使用 `homeFixture.recent`，价格和分析记录不是当前查询结果；小曲线在第75行由三角函数生成。
- `overview/page.tsx:101/105` 共识或冲突接口失败时回退到 `overviewFixture`，正常模式会展示演示结论。
- `lib/dataSource.ts:518` 综合页未来曲线由当前分数加正弦波生成，虽然有示意说明，但不应继续放在正常研究结果主图。
- 首页系统状态标题固定“全部正常”；初值也来自 fixture。失败或不可用时容易与实际状态矛盾。

修正方向：正常模式只用真实结果、真实分析历史或明确空态；独立组件失败只降级该区块，不能回退演示共识。示意曲线仅进入显式 fixture。历史分布若只有汇总统计，也不能当成真实样本分箱。

### P1：未定义的颜色变量造成白色边框

多页使用 `var(--color-line)`，但 `globals.css` 只定义了 `--color-border` 等变量。浏览器实测 `--color-line` 为空；紫微普通宫位边框计算值为 `rgb(232,237,242)`，即接近正文白色。

统一 token 引用；新增共用 `CardBody`、输入控件、表格基元，明确迁移边界，避免统一添加 padding 后与旧页面双重叠加。

### P1：产品页面泄漏实现细节

可见 `ResearchStatus NOT_RUN`、`minor`、`forward`、`not_applicable`、源码路径及原样 `**粗体标记**`。部分按钮仍标注 Phase 2，综合页与上下文栏又有重复导出入口。

主界面使用“尚未运行历史验证”“轻度分歧”“顺行假设”等中文状态；字段码、版本、方法和源数据放入可访问详情。不能隐藏数据不可用、降级与假设警告。React 静态文案使用 `<strong>`，后端解释不应直接作为不受信任 HTML 渲染。

### P1：截图验收存在漏检

- `capture-screenshots.mjs:82` 找不到标题时吞掉失败；首页实际使用 `home-title`。
- 仅固定等待1400ms，再截图；本次时间窗口请求约3.5–4.7秒，原有截图确实停在“正在计算”。
- `--ci` 仅据 console error 失败，不检查布局差距、数据是否就绪或截图是否为目标状态。
- 现有 E2E 未检索到 `toHaveScreenshot` / `toMatchSnapshot`；布局检查主要是无横向溢出、侧栏宽度和背景非白色。
- 04–10 的页面数据层没有完整遵循 fixture 开关；紫微在 `?fixture=ui-reference` 下仍走正常分析，而外壳显示“固定演示数据 · 紫微为 Mock”。因此十页带参数截图不等于十页都是固定数据。

## 5. 合理的偏离：不应照图复制造数

参考图同时包含视觉目标和未经证明的业务结论，两者必须拆开：

- 保留视觉结构、盘面、信息密度、层级与装饰风格。
- 不照搬建议仓位、虚构交易胜率、“必然利好”、默认男命、虚构样本与古籍原文。
- 不用平均分隐藏模型分歧，不用0填充不可用字段。
- 无能力评分体系就用可解释对比矩阵替代雷达图；无 embedding 就用原典—规则—因子关系或真实标签计数替代语义聚类。
- 有确定性月/周结果，可以展示离散点、阶梯或方向色带，并标明规则强度；没必要因为不能做收益预测而彻底放弃可视化。
- 时间窗口本次终态包含 `TIMELINE_CALENDAR_PARTIAL` 和 `TIMELINE_NO_TRADING_DAY`，未来12个月交易日计数为0、周窗口为空。这是输入覆盖问题，必须单列数据门槛，不可画假曲线掩盖。

## 6. 方案选择

| 方案 | 成本/维护 | 效果/风险 | 结论 |
|---|---|---|---|
| 只调整全局 CSS | 低 | 能修字体边框，不能修页面结构、数据缺陷 | 可作为第一步，不足以完成目标 |
| 保留架构，按参考图重排 UI，修展示映射 | 中 | 复用后端、ECharts、已有组件；变更范围可控；能恢复主要视觉特征 | **推荐** |
| 重建前端并更换组件体系 | 高 | 数据适配和交互回归扩大，不能自动解决研究数据缺失 | 当前不建议 |

推荐方案无需新增框架；字体若要跨平台固定，可后续评估有授权的本地字体子集。品牌装饰优先轻量 SVG。避免十页一次性大改后才看效果。

## 7. 分批实施与停点

### A0：建立可复现基线与数据边界

范围：`lib/fixture.ts`、`lib/analysisStore.ts`、截图脚本、E2E 与对应页面数据入口。

1. 冻结参考图版本、viewport、字体和 fixture 的 code/as_of/variant；正常模式与 fixture 严格隔离。
2. 修黄历映射、共识/冲突 fallback、首页固定记录和错误状态；真实统计缺失保持空态。
3. 截图等到指定 ready/error/empty 终态，等待字体与图表完成；记录 HEAD、模式、视口、时间和请求状态。
4. 明确十页都有稳定 fixture，fixture 数据只放 `lib/fixture.ts`，不得进入分析数据库。

验收：关闭后端时 fixture 十页仍独立可看；正常模式任何失败都不出现演示结论；黄历 primary 正确展示。依赖真实数据的子任务与纯视觉任务分别登记。

### A1：外壳 + 首页 + 综合 + 八字样板

范围：`globals.css`、`components/shell/*`、`StockContextBar`、`cards/*`、`bazi/*`、01–03页面。

1. 先定统一 header/sidebar、标题字体和字号层级；修 token、卡片内边距与表格样式。
2. 增加独立山水/星盘/书籍装饰；品牌标题与正文使用不同字体角色。
3. 综合页改为两列独立垂直布局；压缩模型摘要，保留一条显著风险状态。
4. 八字页收紧上下文和盘面高度，恢复正负因素及古籍的首屏位置；长说明进入抽屉。

验收：1672×941 下主要卡片坐标/尺寸与批准布局相近；综合页首屏可见历史摘要和风险；八字页首屏完整看到盘面、时间结构和因素摘要。先展示三页对照图供用户确认视觉方向，再继续其余页。

### B：紫微 / 因子 / 分歧 / 古籍

按第3节逐页恢复工作台布局，复用 A1 基元。紫微首屏展示完整十二宫及右摘要；因子列表选择与详情联动；分歧保留各模型独立方向；古籍支持/反证/中性摘要并列可见。不能仅在滚动很远之后才出现反证提示。

验收：每页一份参考图、当前图、差异说明；fixture 与正常模式相同结构；长文本、多因子、模型失败均不撑坏首屏。

### C：历史验证 / 黄历 / 时间窗口图表

先列出“后端已有/需适配/确实缺失”的指标清单，再接入图表：

- 可从既有持有期统计作柱图，从负对照结果作对比图。
- 无原始样本分箱，不画伪造分布；无净值序列，不画伪造收益曲线。
- 黄历先展示真实原始盘，再按已有逐日数据提供日历；不擅自新增金融吉凶评分。
- 时间窗口先解决日历覆盖输入；若当前上游尚不支持，保留独立阻塞项，UI 仍交付清晰不可用态。
- 新统计计算或后端字段扩展单独走契约、版本和研究验证，不能混入纯 CSS 修正。

### D：验收与归档

1. 固定环境人工核对参考图；把批准后的实现截图作为自动视觉回归基线。
2. 新增 screenshot 回归与关键几何断言；像素差异阈值经样板试跑确定，不随意放宽到总能通过。
3. 1672×941 为主视觉基准；1440×900、1920×1080 检查布局与文本可读性；移动端另列范围。
4. 功能态覆盖 loading/empty/error/unavailable、无样本、支持为空、反证为空、长文本和单引擎失败。
5. 执行项目要求的 typecheck、UI 测试和后端测试；只改显示层不改引擎版本；若计算规则变化，补 Golden 和版本提升。
6. 更新 UI 实现说明、HANDOFF，移除没有视觉证据支持的“1:1完成”表述。

回滚：按批次保留小提交，回退相应展示层提交即可；不做数据库迁移，不改 v1 API，不重算因子以迎合效果图。

## 8. 建议的下一步

先执行 A0 和 A1，交付三页可运行样板及截图。确认整体观感后，再扩展 B/C；不要用十页“功能都在”作为视觉完成依据。

本次结论：**视觉还原验收 NO-GO；保留现有架构进行专项修正可行。** 黄历字段、演示数据隔离和颜色变量是已定位问题；研究数据覆盖、完整业务流程和生产状态不在本次通过范围。
