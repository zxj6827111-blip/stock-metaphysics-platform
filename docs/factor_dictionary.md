## ⚠️ 必读：因子分数的语义

**`direction` 与 `rule_score` 表达的是「传统规则认为的方向与强度」，不是预期收益率，也不是上涨概率。**

```
财星   ≠ 股票上涨
食神生财 ≠ 股票一定上涨
三合   ≠ 股票上涨
```

所有因子都只是**研究变量**。它们与未来收益的关系必须由历史数据回答
（见 `docs/methodology.md` 与 `POST /api/v1/research/run`）。

字段含义：

| 字段 | 含义 | 取值 |
|---|---|---|
| `raw_value` | 原始值 | 标量 / 列表 / 结构化字典；`null` 表示不可用 |
| `normalized_value` | 归一化值 | −1.0 ~ 1.0；`null` 表示不可用 |
| `direction` | **传统规则认为的方向** | `+1` 正向 / `0` 中性 / `-1` 负向 |
| `rule_score` | **传统规则强度** | 0 – 10（不是收益率） |
| `confidence` | 规则判定置信度 | 0 – 1（流派分歧大 / 临界区间时会降低） |
| `availability` | 可用性 | `ok` / `unavailable` / `partial` / `error` |

**数量型因子的 `direction` 一律为 `0`（中性）。**
例如「财星数量 = 4」本身不构成任何方向判断 —— 数量多寡对收益的影响必须由回测回答。

## 一、原局结构因子 `B_NATAL_*`（18 个）

描述股票八字原局的静态结构。这些因子在股票整个生命周期内不变，因此只适合做横截面比较（哪类原局结构的股票表现更好），不适合做时序预测。


### `B_NATAL_001` · 日主强弱

| 项 | 值 |
|---|---|
| 引擎 | `bazi` |
| 类别 | `natal` |
| 默认方向 | `0` |
| 原始值单位 | strength_level |
| 归一化提示 | 身强→+1，偏强→+0.5，中和→0，偏弱→-0.5，身弱→-1 |
| 依赖字段 | `day_master_analysis.strength_level` |
| 标签 | 旺衰 |
| 规则版本 | `v1` |

**定义**：日主在月令与全局中的旺衰等级。传统命理认为身强身弱决定取用方向，但股票不存在『命主』，此处仅作为原局结构特征。

**计算规则**：support/(support+drain) 比值映射：>=0.62 身强 / >=0.55 偏强 / >0.45 中和 / >0.38 偏弱 / 其余身弱

**规则分语义**：传统规则强度分（0-10）。0 表示中性/无该结构，10 表示该结构在传统命理中最强。该分数不使用任何历史行情数据，不代表预期收益率，也不代表上涨概率。

| 归一化值 | 含义 |
|---|---|
| `+1.0` | 用神 / 完全命中（如：流年天干为用神） |

| `0.0` | 闲神 / 中性 / 结构不成立 |
| `−0.8` | 仇神 |
| `−1.0` | 忌神 / 强负向结构（如：冲原局日支） |
| `null` | **不可用** —— 不是 0！ |

## 因子不可用时的行为

当某个因子无法可靠计算时（例如未提供黄历数据、用神未确定），系统会：

```python
_unavailable("B_NATAL_010", code, as_of, "用神未能确定")
```

返回：

```json
{
  "factor_id": "B_NATAL_010",
  "availability": "unavailable",
  "raw_value": null,
  "normalized_value": null,
  "rule_score": 0.0,
  "confidence": 0.0,
  "explanation": "该因子当前不可计算：用神未能确定（按契约返回 unavailable，不猜测数值）",
  "warnings": ["用神未能确定"]
}
```

**禁止**把它当成 0 分参与任何聚合。

## 扩展因子时该怎么做

1. 在 `src/factors/registry/definitions.py` 增加 `FactorDefinition`：
   * `factor_id` 遵循 `{B|H}_{NATAL|YEAR|MONTH|DAY|MONTH}_NNN`；
   * `definition` / `computation` 必填；
   * `rule_score_meaning` 必须声明"不代表预期收益率"；
   * `raw_unit` / `normalized_hint` 说明取值域。
2. 在 `src/factors/registry/compute.py` 增加计算逻辑，或复用通用分支。
3. 跑 `make test` —— `tests/factors/test_factor_calculation.py` 会自动校验：
   * 所有定义都能产出观测；
   * `normalized_value` 落在 [−1, 1]；
   * `rule_score` 落在 [0, 10]；
   * 解释文本中不含肯定式涨跌断言。
4. 更新本文件与 `docs/HANDOFF_PHASE1.md`。
