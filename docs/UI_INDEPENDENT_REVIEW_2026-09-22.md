## 二、公共差距：先解决影响十页的部分

### 1. 字体问题不只是字体文件

当前 `globals.css` 的 `.smp-card-title` 是 13px、font-medium；多个核心卡片正文使用 10–12px。参考图的卡片标题更醒目，数字、标签与说明之间层级更强。只换宋体，无法修正整体“字小、卡片平、主次不明显”的观感。

建议先以综合研判页为样板，试调并截图验证以下层级（是建议起点，不是从原图精确识别的字号）：

- 卡片标题 16–18px，语义主标题使用衬线字体和金色；
- 正文 13–14px，辅助信息 11–12px；
- 关键分数 28–34px；
- 导航文字 14–16px、配合有足够视觉重量的图标；
- 表格行高约 30–34px，正文优先可读，长内容可展开。

不要全站直接放大。先按页面高度预算减少重复说明和无效留白，再提升主信息字号。

### 2. 装饰资产与原图不是同一种质感

参考是细节较丰富的山水、云纹、星盘和书籍视觉。现有 `Decorations.tsx` 是简化 SVG 曲线/几何山体，星盘细节也较少。Logo 已经更接近；接下来反复微调 Logo 的收益低于背景和正文层级调整。

应把山水底纹、星盘、书籍缩略图视为独立资产制作或补充：优先使用合法原始设计资源；否则重绘独立 SVG 或制作低对比背景纹理。保留资源出处。禁止截取参考整页当背景。代码必须保留可交互的真实内容。

### 3. 页面头部过度统一

当前十页几乎使用同一张有边框的 Hero 卡、相同装饰和副标题布局。参考中首页、历史验证、古籍等存在明显页面差异。统一外壳应统一品牌与间距规则，不应抹掉每页构图。

在 `PageHero` 提供有限的页面变体：默认研究页、首页、历史统计页、古籍页。不要复制十套组件。按每张原图记录侧栏宽度、头部底边、上下文栏底边与首个主体卡坐标；原图之间存在差异，不要以一个全局宽度强行宣布逐页 1:1。

### 4. 说明文案占用了主要布局

“研究状态”“数据来源”“传统规则不代表收益”等语义需要保留，但现在经常变成数个全宽大卡。建议：关键不可用/风险状态始终可见；详细方法、原字段和重复解释进入展开区。不能隐藏负对照失效、降级或模型缺失。

## 三、逐页优化落点

### 优先级 A：黄历、时间窗口、历史验证

**黄历：重建左右主栏，保留底部统计区。**

- 左侧约 60%：紧凑的今日历法摘要，下接 20 交易日卡片；首屏应能完整看到两行日期卡。
- 右侧约 40%：选中日期的规则分类、原始依据、可用的时辰信息及数据状态。
- 下方统计区保持“曲线或分组结果 + 统计摘要 + 发现”的横向结构。
- 原图的交易胜率、建议仓位、宜买入/卖出不能照搬。没有该能力时保留合理卡位，显示不可用或改成实际规则依据；不能伪装成待加载数据。
- 当前新候选中第一行日期卡接近页面最底部，主要是摘要与两条说明区过高，不是单纯 margin 太大。

**时间窗口：摘要压缩、主图上移、底部双栏。**

- 顶部四张紧凑摘要卡，展示实际可用的窗口、覆盖与分歧信息；覆盖元数据不应占据整个视觉重心。
- 中部主图约 70%、右侧窗口解释约 30%；可优先展示一个明确选中的实际窗口，不默认留下大面积“暂无数据”。
- 下方左侧月历热力图、右侧未来周排名；完整明细放后面。
- 保留真实阶梯图或方向带。不能为了像原图而把离散观点平滑成连续预测，或增加不存在的共识分数。

**历史验证：先重排，再判断哪些统计能力真正缺失。**

- 紧凑条件栏和常驻研究状态之后，直接显示指标磁贴与两个主图区域。
- 下方放负对照、分组结果和实验明细，保持研究结果与术数规则的视觉分区。
- 新候选虽然补了收益分布/持有期收益卡位，但主要仍排在屏幕最下方；继续补空卡而不重排，只会加长页面。
- 没有序列时不绘制分布、年度收益、策略净值；空态需要短且清晰，同时提供可查看的已有真实实验。

### 优先级 B：综合研判、模型分歧

**综合研判：**三模型评分、共识、冲突形成第一行；第二层以主要图表与证据/风险双栏组织。增大分数、标题、模型图标，减少每卡重复解释。历史摘要与风险必须首屏可见。已有时间窗口能力需要真实接入或提供有效跳转，不能长期保留“Phase 2 尚未上线”的过期文案。

**模型分歧：**恢复醒目的分歧状态摘要、模型观点卡、左侧对比矩阵与右侧归因。无冲突与有冲突都要保留稳定的区域高度和清晰状态。后端没有雷达维度时，以真实因子冲突矩阵替代该区域，不能捏造雷达或第四个量化模型。

### 优先级 C：首页、八字、紫微、因子字典、古籍

- 首页：保留现有骨架，优先精修山水/星盘、搜索区比例、能力卡图标、系统状态和最近分析卡的视觉层级。演示曲线不得进入真实模式。
- 八字：提高卡片标题权重、五行条高度与四柱可读性；时间节点采用更明确的圆形图标和连接结构；完整原盘和展开明细仍可达。
- 紫微：保留十二宫和逐宫明细，优化宫名、主辅杂曜的层级；中央身份区少解释、多结构，右侧摘要紧凑。不要减少星曜或补造格局判断。
- 因子字典：保留 40/60 分栏；加强当前选中行、标签和右侧标题；详情按定义/计算/依赖/证据/验证做紧凑区块。无历史统计可保留简洁状态卡，不让整页成为长说明文档。
- 古籍：保留 55/45 分栏、反证可见性与选中详情；增加书名/卷章的识别元素、清晰的证据类型色标与摘要卡。图像资产不能冒充真实版本书影，装饰封面应明确性质。

## 四、采用什么实施方案

| 方案 | 成本与维护 | 预期效果 | 建议 |
|---|---|---|---|
| 只改颜色、字号和边距 | 低；改动集中 | 首页/八字有所改善，黄历等结构差距仍在 | 不足以完成验收 |
| 公共组件校准 + 三个重点页面重排 + 其余页面精修 | 中等；保留数据层与复用组件 | 能解决主要视觉差距，回归范围可控 | **推荐** |
| 全面重写前端 | 高；交互、fixture 与数据契约需要重新验证 | 不保证还原更好，回归风险最大 | 当前不建议 |

实施顺序：

1. 先冻结一次明确代码/构建/截图身份，停止用不同轮次报告互相证明。
2. 用综合页校准公共字体、卡片、图标和背景；同时用黄历页验证紧凑布局，不以最容易的页面代替难页。
3. 重排黄历、时间窗口、历史验证，再处理分歧中心。
4. 将已确认的公共样式推广到其他页面，补全真实模式和错误态截图。
5. 人工确认差异清单后建立批准基线，随后再执行像素回归。

## 五、验收方式需要调整

- 设计对齐：记录每页关键矩形（x/y/width/height）及首屏必须可见的区域；建议先以主要边界偏差约 8–12px 作为样板校准目标，最终数值由设计确认，不声称这是项目现有标准。
- 内容一致：同股票、同日期、同出生模型、同变体、同数据状态比较；不同来源的指标和原文不能要求像素相同。
- 稳定截图：生产构建，字体加载完毕，禁用 CSS 与图表动画或等待实际渲染完成；等待分析和图表就绪，不能只等待 AppShell hydration。
- V5 `visual-reference.spec.ts` 只等待 `data-app-ready`、fonts.ready 和一个 loading 标记；没有明确图表完成条件。新时间窗口截图曲线只绘出左侧一段，candidate-r4 则完整，提示截图可能抓到动画中间态，不能直接当作数据截断结论。
- V5 新候选左下角存在 Next 开发指示器，正式候选应使用生产构建，避免把开发工具混入像素差异。
- 结构/字体/装饰分别记录差异。SSIM、锚点测量当前为空，不能声称已有这些验收证据。
- 正式回归基线必须来自人工批准的候选，不应反复用效果图中的虚构数字逼迫真实页面通过 3% 门禁。

## 六、此前代码检查的附带结果

这些问题来自 d633106 源码与隔离生产实例，需在正在修改的新工作树中重新核对后修复：

1. **P1：综合页重算没有失效正确缓存。** `overview/page.tsx` 的 force 分支只传 code/variant 给 invalidateAnalysis，读取却带 birthBasis/horizon。两者 key 不同，正常点击会继续命中旧分析；应复用一个完整 AnalysisKey。
2. **P1：分析上下文不贯穿页面。** Sidebar 和模型详情链接没有保留 birthBasis/horizon/asOf；综合页也没有读取 asOf。浏览器打开 `overview?asOf=2024-11-15T14:32:00&birthBasis=ipo_date&horizon=60d`，分析基准仍显示 2026-09-22。不能在不同假设间悄然切换。
3. **P2：研究窗口显示与实际选择不一致。** buildContextFromMulti 固定 horizon 为“20 交易日”；浏览器选择 60d 时详情仍写“预测周期：20 交易日”，JSON 导出快照也未纳入 horizon。应统一响应字段、显示标签和导出身份。
4. **P2：仍存在无动作按钮。** 综合页“查看详情”“历史验证详情”、DataQualityBadge 的“查看详情”只传 action.label，没有 onClick；CardHeader 仍渲染可点按钮。不应将交互闭环写成全部完成。
5. **P2：请求超时未覆盖响应正文。** api.ts 中 JSON 请求在 fetch 返回响应头后即 clearTimeout，再读取正文；文本请求直接 return res.text()，finally 同样提前清除定时器。响应头已到但正文挂起时仍可能无限等待；另“本次分析未被写入”不能仅依据客户端超时保证。
