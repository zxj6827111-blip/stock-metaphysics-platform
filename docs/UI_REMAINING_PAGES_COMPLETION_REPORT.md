## 1. 上轮成果复核：三个真实缺陷（不是报告口径问题）

复核方式是读代码 + 跑真实链路，不接受交付报告的"全部通过"结论。

### 1.1 SSE 休市公告解析返回乱码（决定性）

`scripts/update_trading_calendar.py` 首版用 `requests` 抓上交所公告时，沪深官网 HTML 响应头**不带 charset**，requests 退回 ISO-8859-1，中文全部变成乱码，公告正文一条都匹配不到。

**这个缺陷是被交叉校验抓出来的**，不是靠肉眼：首轮 dry-run 显示 `verified=false`，6 个 mismatch 恰好是 09-25 与 10-01~10-07 —— 正是中秋国庆休市日。修复（显式 `resp.encoding="utf-8"`）后 101 天逐日比对 0 mismatch。

**这是"交叉校验"设计的价值证明**：如果没有与 SZSE 官方逐日口径比对，这个 bug 会让 SSE 公布层把国庆长假当交易日，而且页面上看不出来。

### 1.2 时间窗口接受了"周末规则"结果

`TimelineBuilder._is_trading_day` 只检查 `q.value is None`，**不检查 `q.source`**。日历文件缺失时 `TradingCalendar` 会退化为"周末规则"并标注 `weekend_rule_fallback`，而时间窗口会照单全收 —— 于是春节连休会被当成交易日，且页面上没有任何提示。

`huangli_outlook` 上轮已经堵住了这个洞（只接受 `observed_index_days`），时间窗口这条路径漏了。**已修**：改为只接受 `KNOWN_SOURCES`，并补回归测试 `test_timeline_rejects_weekend_fallback`。

### 1.3 缓存键缺日历版本

`huangli/outlook`、`timeline/{months,weeks,days}` 的缓存键包含引擎与口径版本，但**不含日历内容**。日历一旦更新（新增成交日 / 公布范围推进），进程内缓存会把更新前的窗口当成更新后的返回。

**已修**：`TradingCalendar.version_token`（交易所 + 两层覆盖区间与行数 + 公布层生成时间）进全部相关缓存键。这与"少一个引擎版本号"同类，属于会给出错误答案的缺陷，不是性能问题。

## 2. 当前日期下交易日历的实际覆盖（重新核实，不沿用旧结论）

### 2.1 三层覆盖必须分开

| 层 | 含义 | 本轮实测 |
|---|---|---|
| **行情末日** | `data/import/bars` 快照末日，只有已发生的交易日 | 2026-09-18（快照未动，不改写研究数据） |
| **实测交易日历末日** | 指数**真实成交过**的日期（观测事实） | 1990-12-19 ~ **2026-09-21**（本轮从 09-18 增量更新到 09-21） |
| **官方已公布范围** | 交易所**已公告**的未来安排 | 2026-09-22 ~ **2026-12-31**（101 天，其中开市 67 天） |

旧结论"SSE/SZSE 只覆盖到 2026-09-18，必须用历史 asOf 才能展示未来日期卡"**已不再成立**：那是实测层的边界，不是可用性的边界。

### 2.2 来源（每个都记录 URL 与获取时间）

| 层 | 来源 | 记录位置 |
|---|---|---|
| 实测 | 腾讯指数日线 `sh000001` / `sz399001`（与 `fetch_market_import.py` 同源同口径） | `data/import/calendar/{SSE,SZSE}.csv`（只追加） |
| SZSE 公布 | **深交所官网月度交易日接口**（逐日 `jybz` 开市标志，官方原始口径） | `data/import/calendar/published/SZSE.csv` |
| SSE 公布 | **上交所「休市安排」公告**（公告正文里的休市区间，逐条记录公告号与 URL） | `data/import/calendar/published/SSE.csv` + `_meta.json` |

`_meta.json` 记录：`generated_at`、两条来源 URL 与说明、**5 条上交所公告的标题/URL/发布日/公告号/休市天数**、交叉校验结果、假设说明、边界说明、BSE 说明。

### 2.3 推导规则与交叉校验（为什么这不是"仅排除周末"）

- 公布层的交易日 = **工作日 − 已公告休市日**。依据是交易所自身的休市规则；"周末调休上班日"交易所照样休市（公告明写"9月20日（星期日）…为周末休市"），因此不构成"仅排除周末就推断交易日"。
- 该推导**必须**通过 **SZSE 官方逐日口径**的交叉校验：公布窗口内 101 天逐日比对，`mismatches=[]`、`verified=true`。
- 校验不通过时 `_load_published` **拒绝加载**该层（宁可用不了，也不给错答案），并补了回归测试 `test_cross_validation_failure_blocks_loading`。

### 2.4 边界与降级（实测行为）

| 场景 | 行为 |
|---|---|
| 基准日 = 2026-09-21（今天，交易日） | `mode=trading_days&days=20` → **20 天完整返回**，`status=complete`；`day_sources={observed:1, published:19}` |
| 长假 | 09-25 与 10-01~10-07 **如实缺席**；10-08（节后首日）在列 |
| 基准日 = 2026-12-20 请求 20 天 | 只返回 9 天，`status=partial`，说明"官方尚未公布下一年度安排"，**不照搬上一年** |
| 2027-01-04 | `null` + `source=out_of_coverage`（未知，不是"休市"） |
| BSE（北交所） | 无官方日历导入链路 → `calendar_loaded=false`，**不产出任何日期卡**，不借用沪深日历冒充 |
| 周末在公布窗口内 | 返回 `False` + `source=published_exchange_calendar`（**确定休市**，不是未知） |

### 2.5 更新链路的可重复性

```bash
python scripts/update_trading_calendar.py            # 更新（实测增量 + 公布全量）
python scripts/update_trading_calendar.py --check    # 只校验不写文件
```

- **幂等**：连续两次执行后四个 CSV 的 md5 完全一致（已验证）。
- **只增不删**：实测层取并集；"数据源回得比本地已有覆盖还短"时**默认中断且不写文件**（疑抓取被截断），确认后加 `--allow-shrink` 放行并记录被丢弃日期。
- **不覆盖共享研究成果**：只写 `data/import/calendar/`，不触碰 `data/smp.sqlite3` 与任何研究产物。
- **不改历史计算口径**：增量更新不会删除或改写任何历史交易日，因此不触发 Golden Case 或版本号变更（`calendar_engine_version` 不变）。

### 4.2 因子字典（06）

## 9. 分类结论（功能 / 视觉 / 数据 / 外部限制）

**功能完成**
- 交易日历三层覆盖与官方公布层导入（可重复、幂等、带交叉校验与来源记录）
- 当前日期下的未来交易日查询（黄历日期卡 + 时间窗口逐日）
- 五页信息架构重排与三场景/三栏/四段式结构
- 演示夹具由真实来源冻结 + 可重复的冻结脚本

**视觉完成**
- 五页首屏门禁全部达标（§6 表格），两种视口无内部横向溢出
- 与参考图同尺寸并排对照图已交付（人工目视用）

**数据可用**
- 实测日历 1990-12-19 ~ 2026-09-21；官方公布日历 2026-09-22 ~ 2026-12-31（已交叉校验）
- 真实古籍语料、真实研究实验结果均可读

**外部来源限制（非功能缺陷）**
- **2027 年交易日历尚未公布**（国务院节假日安排通常在当年 11 月发布）。公布窗口因此停在 2026-12-31；页面在越界时显示"部分覆盖/未知"并说明原因，**不照搬上一年**。这是真实外部边界，不是本轮可以解决的缺口。
- **SSE 公布层依赖公告解析**（上交所按假期逐条发公告，没有逐日接口）。因此它的可信度由 SZSE 官方逐日口径的交叉校验担保；校验失败即拒绝加载。
- **BSE 无同等可靠官方日历**，保持显式降级。
- 参考图的字体文件未提供，字体仍为 OFL 的 Noto 系列替代（上轮结论未变）。

## 10. 未验证 / 需人工确认

1. **像素级视觉回归基线**未建立 —— 按任务书 §4 需人工批准后才能作基线；本报告的对照图为目视材料。
2. **真实模式验收用的行情是 synthetic**（隔离测试实例），因此页面上的**研究统计数值**不构成研究结论；日期覆盖、日历边界与三引擎联动的结论来自真实日历与真实快照，与 synthetic 无关。
3. **公布层的推导假设已披露但未消解**：「工作日 − 已公告休市日」依赖"交易日只可能因公告休市而缺失"这一交易所规则。当前 101 天与 SZSE 官方口径完全一致，但**若未来出现临时休市（如极端天气）而公告未发布，SSE 公布层会暂时判断错误**；SZSE 层因为是官方逐日接口不受此影响。该风险已写进 `_meta.json` 的 `assumption_cn`。
4. **历史验证页的真实实验是本机既有产物**（Phase 3D OOS 与事件研究），其中多个实验状态为 `INVALID_CONTROL` / `INCONCLUSIVE` / `EXPLORATORY_NOT_GATED` —— 页面如实展示，**不代表任何策略可用**。
5. **冷启动耗时未再优化**：时间窗口逐日/月度/周度仍为秒级（批量求值 + 进程内缓存），未做后台预计算。
6. 五页的**下半页视觉**（三方四正明细、因子明细、实验明细表）已截图但未逐像素与参考图比对 —— 参考图未提供滚动后状态。
