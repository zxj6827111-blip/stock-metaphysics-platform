## 2. 必须先修的具体问题

### P1：上下文栏用横向滚动隐藏了关键操作

`apps/web/components/stock/StockContextBar.tsx:65` 使用 `overflow-x-auto whitespace-nowrap`，两组内容不可收缩。浏览器实测内容宽约1526px，1672宽度下内部可视区约1373px，1440下约1141px。重新计算按钮右缘约1694px、导出报告右缘约1785px：不主动横向滚动就无法完整操作。

整改：使用“可伸缩标的信息区 + 固定操作区”；1672保留主要字段，1440将出生档案等次要字段收进“详情”；保留股票、基准日期、质量和主要操作。允许窄屏两行，禁止通过继续缩小文字或裁切按钮满足高度测试。详情中的原始字段不可丢失。

### P2：文字与状态表达仍不完整

- `conflicts/page.tsx:83` 的普通字符串包含 `<strong>不代表</strong>`，浏览器直接显示标签。使用 JSX 或纯文本，不对后端字符串使用不受控 HTML 注入。
- `none`、`forward`、`VALIDATED`、ResearchStatus、JSON状态对象、脚本路径和API路径直接进入正文。映射为中文用户状态；源代码、引擎版本及原始值放到可展开“来源与方法”，保留可追溯性。
- 时间窗口写“未来12个月/12周”，fixture实际只有4个月/3周；“下一周”还是2024-11-11~15，而分析基准为11月15日。标题展示实际返回数量和覆盖范围；本周/下周必须依据返回区间与as_of区分，不为凑数伪造。
- `VALIDATED` 不在当前 ResearchStatusBadge 的中文映射中。fixture应使用项目现有合法研究状态，并保持展示数据身份清晰，不能制造正式验证通过的印象。
- 古籍 fixture 页面仍声称“真实 KnowledgeProvider 返回”，页脚版本也存在v1.0.0/v0.2.0不一致。按演示/真实模式显示对应来源，统一从版本配置展示；演示古籍也应使用可追溯原文，未核实条文不可宣称真实引用。

### P2：非支持 fixture 页面存在 SSR/客户端首屏不一致

访问 `/stock/002008/huangli?fixture=ui-reference` 时，服务端为“数据正常”，客户端为“演示模式受限”，触发 hydration mismatch。`ResearchPage` 渲染分支使用依赖 window 的 `isFixtureActive()`。改为服务端与客户端一致的查询参数来源或显式参数；测试必须验证刷新直达、无 hydration/pageerror，且零后端请求。

### P2：公共内容组件尚未真正统一

CardBody已定义，但页面未统一采用，分歧等页存在正文贴边。按区域迁移正文padding，默认14~16px、紧凑区10~12px；不要直接给Card加全局padding导致现有页面双重留白。正文13~14px、辅助信息11~12px，表格与操作保持可读；装饰文字不承担关键含义。
