# AI Narrator 安全规范（Narrator Safety）

> 实现：`src/narrator/narrator.py`、`src/narrator/guard.py`
> 测试：`tests/knowledge/test_narrator.py`（71 项）
> 端点：`POST /api/v1/analysis/{id}/narrative`

---

## 1. 两种模式

| 模式 | 触发 | 说明 |
|---|---|---|
| `template` | **默认**（未配置 LLM） | 由 EvidenceBundle 确定性拼装，逐条遵守 ResearchStatus 约束 |
| `llm` | `SMP_LLM_API_KEY` 已配置且 `prefer_llm=true` | 把 bundle 交给 LLM，**必须**通过 NarratorValidator |

**为什么默认是模板而不是 LLM**：

* 模板是确定性的、可复现的、可离线运行的；
* 它已经能完整表达"三模型各自怎么看 + 共识 + 冲突 + 历史状态"；
* LLM 带来的增量价值是"读起来更顺"，而不是"更多的信息"；
* 因此没有 API Key 时系统**不应该降级成不可用**，而应仍然给出完整、诚实的报告。

`NarrativeResult.mode` 如实返回实际使用的模式，`fallback_reason` 说明退回原因。

## 2. 系统提示中的十条禁令

`SYSTEM_PROMPT` 是**机器可读的固定常量**，不是口头约定。它明确禁止：

1. 重新排八字、重新排紫微、重新算黄历、计算四化或任何术数结构；
2. 修改证据包里的任何分数、方向、置信度、研究状态、历史统计数字；
3. 编造古籍条文（引用必须来自 `classical_support` / `classical_counter_evidence`）；
4. 删除或弱化负面证据（反证、模型冲突、失败的历史检验必须原样呈现）；
5. 使用 `必涨/必跌/稳赚/高概率上涨/历史证明有效/准确率很高` 这类表述；
6. 把 `opinion.score` 说成上涨概率或预期收益率；
7. 在 `NO_SIGNAL` / `NO_REAL_DATA` / `INVALID_CONTROL` / `INSUFFICIENT_SAMPLE`
   状态下暗示有效性；
8. 给出买卖建议、目标价、仓位建议；
9. 把三个模型的观点平均成一个总分；
10. 使用证据包里没有出现过的数字。

**必须做到**：三模型分别陈述；冲突双方与理由都要列出；结尾必须含免责声明；
只使用 bundle 中出现的数字。

## 3. NarratorValidator 的三类检查

### 3.1 禁止词（任何 bundle 下都不允许）

```
必涨 / 必跌 / 稳赚 / 稳赚不赔 / 包赚 / 保本
保证上涨 / 一定上涨 / 必然上涨 / 肯定上涨
保证收益 / 零风险 / 无风险套利
历史证明有效 / 历史证明该术数有效 / 准确率很高 / 准确率极高
高概率上涨 / 大涨在即 / 即将暴涨
```

### 3.2 有条件表述（需要 ResearchStatus 支持）

| 表述 | 需要的状态 |
|---|---|
| 历史验证有效 / 统计上显著 / 胜率较高 | `SUPPORTED_IN_SAMPLE` 或 `SUPPORTED_OUT_OF_SAMPLE` |
| 样本外验证通过 / 具有预测能力 | `SUPPORTED_OUT_OF_SAMPLE` |

### 3.3 状态一致性（必须出现的内容）

| ResearchStatus | 文本中必须出现之一 |
|---|---|
| `NO_SIGNAL` | 未发现稳定信号 / 未表现出超越随机 / 没有统计支持 / 不优于随机 / 无稳定信号 |
| `NO_REAL_DATA` | 合成 / 降级 / 非真实数据 / 不构成历史有效性证据 |
| `INVALID_CONTROL` | 负对照失效 / 对照失效 / 对照不独立 |
| `INSUFFICIENT_SAMPLE` | 样本不足 / 样本量不足 |
| `INCONCLUSIVE` | 不确定 / 证据不足 / 无法判定 / 结论不明确 |
| `NOT_RUN` | 未运行 / 尚未检验 / 没有历史统计 / 未做历史检验 |

任何输出还必须包含至少一条通用免责（`不构成投资建议` / `不代表上涨概率` / …）。

### 3.4 数值一致性（幻觉防护）

文本中的**百分数**必须能在 bundle 里找到对应数值：

* 容差 1 个百分点（文本"58%" 对 bundle 的 58.3% 允许）；
* 相对容差 5%（大数值如收益 12.6%）；
* `0` 永远允许（"样本 0"这类表述必须能通过）。

**为什么只校验百分数**：绝对数字在中文叙述里形态太多（"样本 1248 条"、
"1248 个交易日"、"共 1248"），过度校验会大量误报。
百分数是最容易被 LLM 编造、也最容易被读者当作事实的类型。

## 4. 失败处理：拒绝而不是过滤

LLM 输出未通过守卫时：

* **不静默采用**；
* 退回模板模式；
* `fallback_reason` 写明原因（含具体的 guard violation）；
* `guard_violations[]` 列出每一条违规（`kind` / `detail` / `severity`）。

**为什么不做静默过滤**：静默删词会让输出"看起来通过检查"，
但读者看到的仍可能是被拼接得语无伦次的文本。本项目选择**显式失败**。

---

## 5. 模板模式的内容保障

模板本身也要过守卫。因此模板的每个区块都被设计成"必然合规"：

| 区块 | 合规保障 |
|---|---|
| 三模型观点 | 分别陈述，显式写"不做平均、不做加权成一个总分" |
| 共识与分歧 | 直接消费 `consensus.interpretation`（唯一文案来源）+ `conflict.reasons` |
| 历史验证 | 输出 `ResearchStatus` 字面值 + 对应的状态解读句（`_STATUS_NOTE`） |
| 古籍 | 同时列支持与反证；反证为空时给出警告 |
| 免责 | 固定段落，含"不构成任何投资建议""不代表上涨概率" |

`test_template_respects_research_status` 对六种状态逐一验证模板输出通过守卫。

---

## 6. 已知限制

1. 数值一致性只覆盖百分数，**不覆盖**绝对数字；
2. 禁止词是**字面匹配**，模型用同义改写（如"涨势可期"）可以绕过 ——
   守卫是下限而不是上限；
3. LLM 路径不在自动化测试中真实调用外部服务（用 monkeypatch 桩），
   真实模型的输出质量需要人工抽查；
4. 守卫不校验古籍条文的**准确性**（那需要语料校勘），只校验它们来自 bundle。
