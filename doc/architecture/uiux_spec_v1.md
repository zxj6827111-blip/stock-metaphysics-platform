# 股票玄学多模型研究平台 UI/UX 完整设计规范 V1.0

> 项目：Stock Metaphysics Platform  
> 用途：可直接交给本地 AI、Codex、Claude Code、OpenCode、ZCODE 等作为前端/UI实施基准  
> 目标终端：桌面 Web 优先，兼容平板与移动端  
> 推荐技术栈：Next.js + TypeScript + Tailwind CSS + ECharts + Zustand  
> 设计方向：现代量化研究终端 + 低饱和东方术数视觉语言  
> 核心原则：**盘面优先、证据可追溯、共识与分歧并列、评分不替代解释**

---

# 1. 产品视觉定位

本系统不做传统“算命网站”风格，而定位为：

> **股票术数多模型研究工作台**

设计比例建议：

- 70% 现代金融/量化研究终端；
- 20% 东方术数识别元素；
- 10% 品牌装饰。

禁止：

- 大面积宣纸/卷轴背景；
- 过度红金、祥云、龙凤；
- 只用“吉/凶”颜色表达结果；
- 只给一个总分；
- 用平均数掩盖术数分歧。

# 30. Loading / Empty / Error

```text
✓ 股票资料
✓ 出生档案
✓ 八字排盘
… 紫微排盘
… 黄历
… 因子计算
… 历史验证
… 古籍证据
… AI解释
```

如果紫微未启用：

```text
紫微斗数引擎尚未启用
当前综合研判不包含紫微。
```

绝不能显示“0分”。

某引擎失败：

```text
紫微排盘失败
其他模型结果不受影响
[重试紫微] [技术详情]
```

# 36. 给前端 AI 的强制规则

可写入 `AGENTS.md`：

```text
UI_RULES

1. 页面风格必须偏研究终端，不做娱乐算命风。
2. 评分只是摘要，原始盘面必须可见。
3. 八字、紫微、黄历独立展示。
4. 共识与冲突必须同时支持。
5. 不允许用平均分掩盖冲突。
6. 历史统计与术数判断必须视觉分区。
7. 任一模型失败不能拖垮整个页面。
8. 所有关键组件必须有 Loading/Empty/Error 状态。
9. 所有原始盘面组件必须独立封装。
10. 所有数据卡提供 source/version。
11. 所有图表必须有文本摘要。
12. 前端禁止重新计算术数，只负责展示后端确定性数据。
```
