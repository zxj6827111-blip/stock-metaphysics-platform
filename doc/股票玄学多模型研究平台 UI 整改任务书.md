现有报告是整改依据，不代表当前代码永远不变。启动时重新记录 HEAD、工作区修改和运行条件，核实问题是否仍存在。

**范围与禁止事项：**

- 不升级依赖、不引入新组件框架，不部署 NAS 或云服务器。
- 不用整页截图或裁剪截图替代组件；装饰可用独立 SVG，文字、盘面、表格、图表必须真实渲染。

**每批完成后停止，提交证据。只有收到明确的“本批验收通过，继续下一批”，才进入下一批。自测通过不等于用户验收通过。**

## 二、统一视觉与数据标准

### 1. 视觉标准

原 PNG 是视觉方向的依据；研究规则决定哪些业务文案和数字可以展示。

| 项目 | 本次统一标准 |
|---|---|
| 主验收尺寸 | 1672×941，浏览器缩放100%，deviceScaleFactor=1 |
| 兼容检查 | 1440×900、1920×1080；移动端专项适配不纳入本轮 |
| 公共外壳 | 顶栏64px、侧栏232px；参考图个别页面侧栏宽度不同，本次统一 |
| 内容间距 | 主内容左右14–16px，卡片间距12px，内容区padding统一为12–16px |
| 字体角色 | 品牌、大标题、卡片标题使用宋体风格；正文使用中文无衬线；代码和数值使用等宽字体 |
| 字号起点 | 首页标题52px，详情标题42px，卡片标题17–18px，正文13–14px，辅助信息11–12px |
| 视觉元素 | 恢复低亮度山水、精细星盘、金色标题、印章及书籍装饰；集中于头图区和边角 |
| 数据颜色 | 涨跌、模型方向、五行、支持/反证分别定义语义，不混用 |
| 可读性 | 不通过缩小所有文字、隐藏溢出或整页缩放来塞入首屏 |

字体先使用有明确回退顺序的系统字体，不下载来源不明字体。视觉回归必须固定操作系统、浏览器和字体环境。

标题、盘面、核心结果优先；长解释进入详情抽屉或展开区。**数据不可用、降级、研究未运行及运限假设必须保持可见。**

### 2. 数据标准

- 正常模式只展示真实 API 结果或明确空态。
- `?fixture=ui-reference` 才启用演示数据；十页必须完整支持，且显著标识演示模式。
- 演示数据集中于 `lib/fixture.ts`，不能触发分析落库或混入正常模式缓存。
- fixture 固定股票、分析时点、变体、研究状态和图表数据；截图不得随当前日期变化。
- 各模型、证据、历史验证、时间窗口独立处理加载和失败，单一区块失败不抹掉其他成功结果。
- 前端只做字段映射、格式化、筛选和可视化，不重新计算术数或补造研究结果。
- 暂缺后端能力时显示“不可用及原因”，另列后端依赖清单，不擅自扩大本轮范围。

## 三、分批整改任务

### 批次 A：展示正确性与验收基础

**目标：先消除错误显示，建立可靠的十页截图条件。**

执行内容：

1. **修复黄历映射。**  
   根据真实响应类型读取 `huangli.primary` 和 `days`，逐项核对干支、农历、节气、宜忌、冲煞、神煞方位。禁止用宽泛类型和多级猜测回退掩盖字段错误。

2. **清除正常模式的演示回退。**  
   共识或冲突请求失败时，显示该区块错误与重试入口，不能返回 fixture 的正常结论。

3. **修复首页最近分析。**  
   改为“本会话最近分析”，从正常模式成功分析结果记录中展示最多3条。没有记录时显示引导空态；无真实行情序列时不显示价格走势图。fixture 保留参考图用的固定三张卡。

4. **修复系统状态。**  
   “全部正常”必须由实际状态推导。初始为加载态，请求失败为未知或连接失败；不得沿用演示状态和延迟。

5. **移除正常模式的正弦示意曲线。**  
   综合页时间窗口接已有月周结果；未取得结果时保留模块空态。没有真实分箱数据时，不把近似分布标成样本收益分布。

6. **修复共用样式缺陷。**  
   统一边框 token，消除未定义的 `--color-line`。新增明确的卡片内容区基元，逐处迁移，避免与旧页面padding叠加。

7. **补齐十页 fixture 和截图状态。**  
   截图脚本按页面等待指定成功、空态或错误终态；等待字体及图表渲染完成。超时必须失败，不能吞掉异常或只等固定1400ms。

8. **整理产品文案。**  
   用户界面显示中文状态，内部枚举和源码信息移入详情；修复直接显示的 `**` 标记。保留 source/version 和原始数据入口。

**验收：**

- 阻断后端请求后，十页 fixture 仍可完整渲染，且没有分析写入请求。
- 正常模式请求失败时不出现演示共识、演示最近分析或假曲线。
- 黄历使用真实响应形状能显示原始盘面。
- 系统状态能正确区分加载、正常、不可用和失败。
- 原有核心交互不回归。

**停点 A：提交测试结果和十页基线截图，等待验收。**

### 批次 B：公共外壳与三页视觉样板

**目标：先让首页、综合研判、八字详情达到用户认可的视觉方向。**

共同修改：

- 统一品牌字体、标题、导航图标、选中态、卡片边框和表格。
- 实现独立可复用的山水、星盘、印章装饰，不使用参考截图裁剪素材。
- 股票上下文区采用明确栅格安排，避免按钮自然换行撑高。
- 合并重复导出入口；已实现操作调用真实功能，未实现操作清晰标识，不伪造成功。

| 页面 | 必须实现的布局 |
|---|---|
| 首页 | 左侧标题与搜索、右侧星盘；下方最近分析与系统状态约2.1:1；底部四张能力卡 |
| 综合研判 | 第一排模型/共识/冲突约50:29:21；下部左58%为时间窗口与历史摘要，右42%为证据与质量，左右独立堆叠 |
| 八字详情 | 五行/四柱/摘要约26:45:29；时间结构横向展示；正负因素并列；古籍区紧随其后 |

首屏目标：

- 综合页模型区顶部约250px、高度约195px；历史摘要顶部不晚于760px。
- 八字盘面顶部约245px、高度约270px；因素区顶部不晚于710px，古籍区标题不晚于890px。
- 数值作为标准fixture的布局目标；真实长文本通过摘要和详情层处理，不裁掉原始数据。
- 八字干支恢复五行颜色，但不得改变盘面值。
- 运限不可用时保持对应位置的说明，不照搬参考图里的默认男命或虚构大运。

**验收：**

- 三页参考图、整改前、整改后并排对照。
- 综合页首屏可见历史验证和风险摘要。
- 八字页首屏完整可见盘面、时间结构和因素摘要。
- 1440与1920宽度下无水平溢出、按钮遮挡或不可访问内容。
- 所有文字、表格和盘面均为真实组件。

**停点 B：必须由用户确认三页整体观感，才能复制到其他页面。**

### 批次 C：紫微、因子、分歧、古籍四页

沿用已确认的样板，不重新创造另一套设计语言。

| 页面 | 执行要求 |
|---|---|
| 紫微 | 左63%展示完整十二宫，右37%展示命身摘要、四化、运限与研究状态；三方四正放左下。保持宫位环序及顺逆假设正确 |
| 因子字典 | 左40%列表、右60%详情；列表选择与详情联动；按现有字段提供搜索和筛选；每页20条；定义、计算、证据、历史验证分区 |
| 模型分歧 | 顶部结论横幅；下部左侧三模型观点和比较矩阵，右侧冲突原因；不增加虚构量化模型或能力雷达 |
| 古籍证据 | 左55%证据列表，右45%摘要及原文—解释—因子链；支持、反证、中性计数和入口首屏同时可见 |

补充约束：

- 古籍检索若仍是结果内筛选，明确命名为“当前证据内筛选”，不得冒充全库检索。
- 无历史统计、相关性或相似案例数据时使用明确空态，不复制效果图数字。
- 支持与反证同等可访问，不通过默认折叠隐藏反证存在。
- 详细方法、版本和授权信息可以展开查看，但不得删除。

**停点 C：逐页提交视觉与功能证据，等待验收。**

### 批次 D：历史验证、黄历、时间窗口三页

**目标：恢复图表工作台结构，同时如实呈现数据能力。**

| 页面 | 执行要求 |
|---|---|
| 历史验证 | 顶部真实研究状态及已有条件；下方统计指标、持有期对比、负对照和明细。传统规则摘要与历史统计分区，规则分数不得占据主要统计区 |
| 黄历 | 左60%今日原始黄历与日期视图，右40%研究映射与因子摘要；宜忌与金融结论分开；仅展示API提供的日期，不将自然日擅自标为交易日 |
| 时间窗口 | 顶部可用性摘要；左68%月周观点图与明细，右32%解释及冲突；使用离散点、方向矩阵或色带，不对缺失月份插值 |

确定的数据处理方式：

- 持有期统计 → 柱状对比图；已有负对照结果 → 对比图。
- 没有样本分箱 → 不画收益分布；没有净值序列 → 不画净值曲线。
- 模型各自独立展示，不新增平均“综合预测分”。
- 日历缺失、模型不可用、研究未运行均保留图表区域，提供可读原因。
- 加载态使用固定区域骨架；成功为空、错误和未运行不能混为一种状态。
- 当前日历覆盖不足作为独立后端依赖记录，本轮不修改交易日历、行情源或研究流水线来强行完成图表。

**停点 D：同时提交有数据fixture、真实API模式及异常状态截图，等待验收。**

## 四、测试与验收要求

### 1. 必测场景

| 场景 | 通过条件 |
|---|---|
| 正常模式 | 数据来自API，缺失字段保持不可用语义 |
| fixture模式 | 十页固定、明确标识、不依赖后端、不污染正常缓存 |
| 黄历响应 | `primary` 有数据时正确显示，字段缺失时明确提示 |
| 单模型失败 | 其他模型仍可见，不以0分或演示数据补足 |
| 共识/冲突接口失败 | 独立错误态，不显示“无冲突”假结论 |
| 无历史样本 | 明确显示未运行或样本不足，不生成统计图数字 |
| 证据边界 | 支持为空、反证为空、长原文均有正确布局 |
| 时间窗口 | 有数据、部分缺失、全部缺失、超时分别处理 |
| 长文本与大列表 | 不撑坏主布局，完整内容仍可访问 |
| 关键交互 | 搜索、页面跳转、因子选择、证据展开、变体切换、重新计算及已有导出可用 |

业务缺陷应补回归测试；纯装饰修改通过截图验收，不编写无意义的实现镜像测试。

### 2. 检查命令

在前端目录执行：

```text
npm run typecheck
npm run build
npm run test:e2e
```

UI测试应针对已启动且配置正确的前端服务。最终执行仓库要求的 `make test`；Windows无make时使用项目虚拟环境运行等价的 `python -m pytest -q`。

记录实际命令、退出码和失败日志。现有 lint 命令若不可用，报告现有配置问题，不通过跳过检查或升级框架伪造通过。

### 3. 视觉判定

- 与原效果图比较：人工核对栅格、卡片比例、首屏锚点、字体、装饰和信息层级。
- 与批准后的实现基线比较：固定环境自动截图回归，初始采用 `threshold=0.2`、`maxDiffPixelRatio=0.005`。
- 动态时钟应固定或局部遮罩，禁止遮罩盘面、图表和主要内容来规避差异。
- 阈值失败先查原因，不得自行放宽；基线更新必须附可见差异和理由。
- 不以“无报错”“元素存在”代替视觉通过，不编造还原度百分比。

## 五、每批交付格式与首次启动指令

每批交付必须包含：

1. **结果**：完成项、未完成项、保留差异。

证据分别标注 `fixture`、正常API、失败态，不能把不同来源截图合并宣称“全部通过”。按批次保留可独立回退的修改，不自动提交无关文件或执行部署。
